# Swellwright: план разработки

Статус: **план**, кода нет. Подпись: «Swellwright: развёртывание и сопровождение нод Remnawave». Проект **неофициальный**, не часть Remnawave и не заявляет связи с ним.

## 1. Назначение
Единая веб-консоль и API для всего жизненного цикла парка Remnawave: серверы (инвентарь, SSH, терминал), развёртывание и сопровождение нод, DNS, сертификаты, объекты панели (профили, хосты, сквады, шаблоны, хопы), обновления, безопасность, резервные копии, мониторинг и зонды из разных сетей. Сюда входит всё, что администраторы обычно делают разрозненными скриптами (развёртывание, переименование и замена нод, правка DNS, раскатка шаблонов подписки), и то, что скриптами решается плохо: возобновление после сбоя, расписания, контроль дрейфа, мониторинг, терминал, ролевая модель.

## 2. Цели и не-цели
**Цели**
- Полное покрытие сценариев парка (каталог в `03-scenarios.md`: около 90 сценариев) без «ручных дыр»: любое действие над нодой, DNS, панелью или хопами можно сделать из Swellwright, с планом, подтверждением, проверкой и откатом.
- Полная интеграция с Remnawave 3.4.x: все 218 операций API доступны через типизированный клиент; удобные сценарии над ними; расширение возможностей панели (цепочки хопов, рассинхрон и конвенции, канареечные раскатки, снимки конфигурации, зонды).
- Интерфейс максимально похож на панель Remnawave: тот же стек и те же библиотеки (React 19, Mantine 9, TanStack Query, Zustand, React Router 7, Zod, Tabler icons, Monaco, xterm.js).
- OpenAPI 3.1 как первоклассный артефакт: документация (Scalar), типизированные SDK, CLI и MCP строятся из него.
- Секреты и постоянные параметры хранятся в зашифрованном хранилище Swellwright; в сценариях вводится только изменяемое.
- Docker, как у панели; работа парка не зависит от Swellwright (ноды автономны).
- **Открытый универсальный проект (AGPL-3.0-only, GitHub для всех).** Ядро подходит любому администратору Remnawave; **весь код публичен**, включая интеграцию с API RU-CENTER и схему узла self-steal (они оформлены плагинами и примерами); не публикуются только **данные экземпляра** (домены, IP, имена нод, токены, пароли, ключи, результаты), см. `13-plugins-and-opensource.md`.

**Не-цели**
- Не заменяет панель и не обслуживает клиентов как биллинг (модуль «Пользователи» опционален и ограничен администрированием).
- Не публичный сервис и не SaaS; один владелец экземпляра, возможна небольшая команда.
- Не клиент VPN и не хранилище пользовательского трафика.
- Не требует агентов на нодах (по умолчанию agentless по SSH; агент опционален и позже).

## 3. Принципы
1. **Только чтение по умолчанию.** Любое изменение проходит цикл: план, подтверждение, применение, проверка, при сбое откат.
2. **Каждое изменение обратимо или явно помечено необратимым** (запись отката в журнале, снимок до изменений).
3. **Идемпотентность шагов.** Повтор безопасен.
4. **Долговечное выполнение.** Состояние запуска в базе: сбой воркера, перезапуск и обрыв SSH не теряют ход; шаги на ноде идут отдельным процессом и переживают обрыв.
5. **Минимум прав и минимум показа секретов.** Токены с scopes, SSH-сертификаты, редактирование вывода, секреты не покидают хранилище, кроме нужных шагов.
6. **Автономность парка.** Выход Swellwright из строя не ломает ноды и панель; аварийный доступ остаётся (резервные ключи вне Swellwright, прямой SSH на ноды).
7. **Наблюдаемость по умолчанию:** этапы, время, оценка остатка, журнал вывода, события, метрики.
8. **Версии закреплены**, обновления только осознанно; источники зависимостей проверяются.
9. **Факт и гипотеза различаются:** рекомендации помечаются «измерено / сообщество / предположение».
10. **Установщик и эталон ноды версионируются**: любое изменение нод идёт через версионный артефакт.
11. **Не доверять выводу нод:** вывод очищается от управляющих последовательностей, не исполняется, не попадает в HTML без экранирования.
12. **Один источник правды по объектам панели:** панель; Swellwright хранит снимки, намерения и журнал.
13. **Универсальное ядро и плагины:** ядро не знает про конкретного провайдера DNS, хостера, оператора или схему имён; специфика подключается и отключается плагинами без правки ядра.

## 4. Покрываемые возможности
- Развёртывание, переразвёртывание, переименование, замена и вывод нод: этапы, журнал, откат панели и сервера, DNS через драйверы (включая API RU-CENTER (NIC.RU)), шаги ожидания, обработка типовых сбоев.
- Установщик ноды и движок ноды (снимок, откат, страховка SSH/UFW) как версионные артефакты Swellwright; движок требует python3 на ноде.
- Сопровождение парка (сценарии P/N с планом, диффом и откатом): синхронизация адресов хостов с IP нод, создание и раскатка шаблонов подписки, настройка sniffing и правил DNS/SMTP профиля, ротация ключей REALITY, ограничение порта API ноды, поочерёдная перезагрузка нод, проверка обновлений.
- Резервные копии панели: шифрование (CMS), таймеры, проверка восстановления в одноразовом Postgres.
- Зонды: замеры нод из разных сетей, проверка отпечатков и целых конфигов подписки Xray в песочнице.
- Контрактные тесты и проверка тел запросов по спецификации OpenAPI Remnawave (3.4.x).
- Эталон ноды (baseline) и справочник «факт / гипотеза».
- Безопасные политики (policy engine, `08-engine.md`): по умолчанию только чтение; бэкап и откат; учёт влияния правки общего профиля; канарейка и малые группы; сохранение запасного доступа; один параметр за раз; различие факта и гипотезы; изменения нод отражаются в установщике.
- Настраиваемые конвенции: шаблон remark, `vlessRoute`, хоп-сервис, маркер тестовых объектов 🧪, address=IP.

## 6. Проектные решения
| Вопрос | Решение | Последствия |
|---|---|---|
| Размещение | **на одном хосте с панелью или на отдельном сервере** (поддерживаются оба варианта) | при размещении рядом с панелью: отдельная docker-сеть и пользователь, свой Postgres и Valkey, лимиты ресурсов, firewall, без `docker.sock`; меры в `05`, `09` |
| Терминал | **входит в состав; пользователь вводит реальные данные SSH на каждую сессию** | терминал не использует сохранённые секреты; данные только в памяти сессии; запись по выбору; `05` |
| Способы SSH-доступа | **пароли, сертификаты, ключи: любые, настраиваемые** | центр сертификатов не навязывается; все способы поддерживаются; рекомендации политиками; `05` |
| Токен панели | **один токен** | по умолчанию `*`; профиль наименьших прав остаётся опцией; `04` |
| Лицензия | **AGPL-3.0-only** | совместима с кодом панели; DCO; проверка лицензий; `13` |
| Публикация | **GitHub для всех; публично всё, что является кодом** (включая RU-CENTER и схему узла self-steal как плагины и примеры); данные экземпляра не публикуются | один репозиторий `swellwright`; `13` |
| Документация, вклад | **английская основная, русская дополнительная; DCO** | `13` |
| Сторонние плагины | **декларативные драйверы и контейнеры сразу** | сайдкары без `docker.sock`; `13`, `09` |
| Уведомления | **Telegram первым** | бот и согласования кнопками (низкий и средний риск) |
| cert-sync (распространение сертификатов на ноды) | **подключаемый механизм, публикуется** | интерфейс `CertDistributor`; плагины `certs-rsync` и `certs-cron-script` (адаптер к внешнему скрипту синхронизации сертификатов, команда, список нод и пользователь в настройках); `13` |
