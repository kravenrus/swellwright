# 07. Интерфейс и UX

Цель: интерфейс выглядит и ведёт себя как панель Remnawave (администраторам Remnawave он сразу знаком) и при этом даёт принципиально больше: планы, живые запуски, дифф, терминал, мониторинг.

## 1. Основа
- Те же библиотеки, что у панели (версии сверены с фронтендом панели Remnawave 3.4.x): React 19, Vite, **Mantine 9** (core, notifications, modals, spotlight, code-highlight, form, dates, dropzone, charts), TanStack Query 5, Zustand 5, React Router 7, Zod 4, i18next, иконки Tabler, Monaco, `@xterm/xterm` (+ fit, webgl, unicode11, web-links).
- Тема: тёмная по умолчанию, светлая как вариант; цвета, радиусы, размеры, шрифты **берутся из темы панели** (код, компоненты и тема открытого фронтенда панели используются как основа: AGPL-3.0, с сохранением уведомлений об авторских правах и пометкой изменений, см. ADR 0011; название и знак Remnawave не копируются), собственные токены лежат в `packages/ui`.
- **Визуальный язык (сверен с фронтендом панели 3.4.11):** тёмная палитра панели (фон `#161b22`, текст `#c9d1d9`), основной цвет cyan (оттенок 8), Montserrat для текста и Fira Mono для кода и терминалов (размещаются у себя, а не берутся из CDN), иконки Tabler, радиус `md`, полупрозрачные карточки, тонированные кнопки «light», бейджи с контуром и вкладки-таблетки. Таблица токенов и исходные файлы панели в [wireframes/README.md](wireframes/README.md#визуальный-язык).
- Таблицы: Mantine DataTable/Mantine React Table как у панели (используются форки панели `@kastov/*` как справочник, при необходимости обычные пакеты), виртуализация для больших списков.
- Графики: Mantine Charts (Recharts); тепловые карты и временные ряды зондов пишутся на их основе (Highcharts в панели имеет собственную лицензию, не берём).

## 2. Каркас
- **AppShell:** компактный макет панели по умолчанию: шапка со строкой бренда (64 px: логотип, переключатель панели, лоток активных запусков, поиск Spotlight Ctrl+K, тревоги, пользователь) и строкой навигации (52 px) со сгруппированными разделами и выпадающими меню; плавающее левое меню как вариант; каждая страница открывается карточкой-шапкой (значок, заголовок, описание, действия), как в панели.
- Разделы навигации: Обзор; **Парк** (Серверы, Ноды, Цепочки, DNS, Сертификаты); **Операции** (Запуски, Сценарии, Расписания); **Мониторинг** (Зонды, Тревоги, Отчёты); **Панель** (Профили, Хосты, Сквады, Шаблоны, Подписки, Плагины, Биллинг, Пользователи, Консоль API); **Безопасность** (Хранилище, Пользователи и роли, Токены, Сессии, Аудит); **Настройки** (Общие, Конвенции, Эталоны, Политики, Интеграции, Уведомления). Документация это кнопка в шапке.
- Адаптивность: работает на телефоне (аварийный сценарий «посмотреть и откатить»).

## 4. Ключевые паттерны
- **Панель плана (Plan drawer)** для любого изменения: что изменится (дифф), влияние (рестарты, сколько нод, время), риск и требуемые согласования, откат (что вернётся, что нет), блокировки; кнопка «Запустить» активна только после просмотра. Это прямое воплощение политики P-001 (по умолчанию только чтение, запись требует утверждённого плана).
- **Живой запуск:** шапка с общей полосой и оценкой остатка, этапы со статусами, вывод шага в стиле терминала с серым разделителем, цвета и значки согласованы с Tabler: ✔ выполнено, ✖ ошибка, ⚠ предупреждение, ℹ информация, ▶ идёт, ● ожидает, ↺ откат (заменяются на SVG-иконки; режим «текстовые значки»).
- **Дифф везде:** профили, шаблоны, хосты, настройки, конфиги нод (side-by-side, unified).
- **Копирование:** кнопки «Копировать как текст» (без ANSI), «Скачать журнал»; вывод копируется как обычный текст.
- **Согласования:** отдельный центр, карточка с планом и кнопками одобрить, отклонить, запросить изменения; для высокого риска ввод подтверждающей фразы.
- **Формы-мастера:** развёртывание (шаги: сервер, параметры, DNS, панель, доступ, проверка, план, запуск); переименование; цепочка хопов; подключение панели; подключение DNS.
- **Секреты в формах:** поля-маски, выбор «взять из хранилища», видимость только в момент ввода, подсказки где взять (RU-CENTER и др.).
- **Пустые и ошибочные состояния:** понятные сообщения и действия «что делать дальше», скелетоны загрузки, повтор запроса.
- **Поиск и команды:** Spotlight (серверы, ноды, хосты, запуски, команды вроде «запустить проверку на узле XX-02»), горячие клавиши.
- **Уведомления:** Mantine Notifications для коротких событий, центр уведомлений для истории.
- **Локализация:** ru и en, формат дат и длительностей, 24-часовое время, без эмодзи в интерфейсе (флаги стран у хостов показываются как данные панели).
- **Доступность:** клавиатура, фокус, контраст (проверка axe), не только цвет для статусов.

## 5. Терминал
Вкладки, выбор сервера, шрифт и размер, копирование и вставка с подтверждением многострочного ввода, поиск, запись, индикатор «сессия записывается», индикатор повышенных прав, тайм-аут простоя, кнопка «закрыть у всех» для администратора.

## 6. Технические требования
- Состояние сервера в TanStack Query (кэш, повторы, инвалидация по событиям WebSocket), локальное в Zustand.
- Ленивая загрузка тяжёлых компонентов (Monaco, xterm, графики), бюджет размера бандла.
- Визуальные регрессии и e2e на Playwright, проверки доступности.
- Единые компоненты в `packages/ui`, Storybook как каталог (опционально).

## 7. Язык и универсальность
Интерфейс английский по умолчанию, русский полный (i18next 26, тексты в `packages/i18n`, ADR 0020): ключи проверяются компилятором по английскому каталогу, а тест роняет сборку, если язык с ним расходится; язык выбирает человек (меню учётной записи, запоминается в браузере), иначе язык браузера, иначе английский; даты и числа следуют языку; тексты ядра без привязки к стране или провайдеру; вклады плагинов описываются декларативно (страницы настроек, виджеты) и рисуются тем же набором Mantine-компонентов; произвольные React-бандлы плагинов не загружаются в первой версии.

Аннотированные макеты ключевых экранов (обзор, карточка сервера, план и согласование, карточка запуска, запечатанное хранилище, хранилище, первый запуск, раскладки для телефона) лежат в [`wireframes/`](wireframes/README.md).
