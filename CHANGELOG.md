# Changelog

All notable changes are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added
- Initial repository skeleton: license (AGPL-3.0-only), DCO, code of conduct, contribution and security policies.
- Design documents (English overview, full Russian design set and its English translation), architecture decision records.
- Annotated UI wireframes: overview, server card, plan and approval, run card, sealed vault, vault, first-run setup and phone layouts.
- Phase 0 monorepo skeleton: pnpm workspaces, Turborepo, strict TypeScript, ESLint, Prettier and a CI build job.
- Phase 1 first slice: route registry and OpenAPI 3.1 generator (`packages/contracts`), NestJS 12 API with health, readiness, version and the API description (`apps/api`), the Remnawave panel theme and application shell (`packages/ui`, `apps/web`), development compose file, ADR 0012.
- Phase 1 data layer: Prisma 7 with the first model `User` and its migration (`packages/db`), a shared `Database` client, `/ready` that also requires the migrations to be applied, a checksum check of the Prisma schema engine, database commands and CI steps, ADR 0013.
- Phase 1 sign-in: first-run setup with a one-time token, password (Argon2id) and authenticator (TOTP) sign-in, recovery codes, sessions, lockout, `Origin` check, sign-in screens in the console, routes that declare their authentication level, ADR 0014.
- Phase 1 roles and audit: a closed permission catalogue and the five built-in roles as fixed sets, a permission on every signed-in route enforced by a guard and checked by a test, `GET /roles`, the append-only audit chain (`audit_events` with database triggers, SHA-256 links, advisory-locked numbering), records for first-run setup, sign-in and refused access, `GET /audit` and `POST /audit/verify-chain`, the Roles and Audit pages of the console, ADR 0015.
- Phase 1 users and credential reset: invite a user (no password, a one-time 72-hour invitation), change role, status, display name and e-mail, reset credentials, choose a password with an invitation, change your own password, the rule that there is always an active owner, `node dist/admin.js` (`users`, `reset-credentials`) for the host when nobody can sign in, the Users page, the invitation screen and the password dialog of the console, ADR 0016.
- Phase 1 step-up authentication: a session is elevated by the sign-in and renewed with an authenticator or recovery code (`POST /auth/step-up`, five minutes by default, `SW_STEP_UP_MINUTES`), routes declare `stepUp` (OpenAPI `x-sw-step-up`) and answer 403 `step_up_required`, permissions that always need it (`users:write`, `vault:manage`, `vault:reveal`, `terminal:use`) are checked by a test, user management and password change now need it, the console asks for a code and retries, ADR 0017.
- Phase 1 plugin manifest and discovery: the strict `swellwright.plugin.json` schema and the permission diff in `packages/plugin-api` (relative paths inside the plugin, public `host:port` network permissions, declarative drivers only for REST kinds), `discoverPlugins` in the API that describes plugins as `available`, `incompatible` or `invalid` with every reason without loading anything (no links followed, no install scripts, ids unique, earlier root wins), ADR 0021.
- Phase 1 i18n: the texts of the console in English and Russian (`packages/i18n`, i18next 26 and react-i18next 17), keys checked by the compiler against the English catalogue, a test that fails the build when a language differs (keys, plural forms, placeholders, untranslated copies), a language switch in the account menu (the person's choice, else the browser's, else English), dates and numbers that follow the language, ADR 0020.
- Phase 1 deployment: a container image (`Dockerfile`, pinned base image, pnpm and Prisma engine, non-root, read-only) with the API, the console and the migration tool, the API serves the console with a content security policy and cache rules (`SW_WEB_DIR`), `SW_TRUSTED_PROXIES` for the address of the client behind a proxy, `deploy/compose/docker-compose.yml` (PostgreSQL, Valkey, a one-shot `migrate`, the server), a CI job that starts the stack and runs `scripts/smoke-test.sh`, Dependabot for the image, the compose file and the actions, ADR 0019.
- Phase 1 secrets vault: a random key wrapped under the passphrase (Argon2id) and under a one-time recovery key, a data key per secret version bound to its id, version and type, sealed on start, unseal and seal, store, rename, replace and delete secrets, reveal with a step-up and an audit record, values write-only, 423 `vault_sealed`, the Vault page of the console, ADR 0018.
- Phase 1 sessions: every user lists and ends their own other sessions, `sessions:read` and `sessions:revoke` (with a step-up) for the sessions of others, the Sessions page of the console, `session.revoked` in the audit chain, six new permissions in the catalogue (`sessions:*`, `tokens:*`, `audit:export`), OpenAPI 0.7.0, ADR 0022.
- Phase 1 API tokens: `Authorization: Bearer swt_...` for the CLI and integrations (only the hash stored, shown once), a subset of the owner's permissions never including one that needs a step-up and cut down to the owner's role on every request, expiry, address restriction, the route authentication level `any`, creation with a step-up, own tokens open to everyone, `tokens:read` and `tokens:revoke`, rate limit on wrong tokens, `token.created`, `token.revoked` and `auth.token.denied` in the audit chain, the Tokens page of the console, OpenAPI 0.8.0, ADR 0023.
- Phase 1 user deletion and language: delete a disabled user with everything that hangs on the account while the audit log keeps what it did under its name (`DELETE /users/{id}`, step-up, `user.deleted`), and a language of one's own kept on the account (`PATCH /auth/preferences`; `users.language` is empty until someone chooses, the console then follows the browser and applies a saved language after sign-in), a Delete action on the Users page, ADR 0026.
- Phase 1 vault key rotation: change the passphrase (works while sealed, nothing re-encrypted), issue a new recovery key, replace the key-encryption key (all or nothing, a new recovery key is issued) and encrypt every secret under a fresh data key, each with a step-up and, for the first three, the passphrase again; one in-process queue for everything that touches the key; only failed passphrase tries count towards the limit; last-rotation times in the vault status and the key rotation section of the Vault page, OpenAPI 0.9.0, ADR 0024.
- Phase 1 audit export and checkpoints: export pages of the log with the fields their hashes cover (`audit:export`, step-up), offline verification of an export file (`node dist/admin.js audit-verify`), checkpoints of the chain head signed with a key derived from `SW_AUTH_KEY` that is not in the database (create and check through the API or the host command), which catch a consistently rewritten history and a cut-off tail, `audit.exported`, `audit.checkpoint.created` and `audit.checkpoint.verified` in the chain, export and checkpoint controls on the Audit page, OpenAPI 0.11.0, ADR 0025.
- Phase 1 plugin enabling: an approval tied to the digest of every file of a plugin (`GET /plugins`, `POST /plugins/{id}/enable` with the digest that was shown, `.../disable`; `plugins:read` for every role, `plugins:manage` with a step-up for the owner), a plugin that is gone, unusable or changed is switched off on the next read and at start with a `plugin.disabled` record, `plugin.enabled` records, Settings → Plugins with what a plugin asks for and what changed since it was approved, `SW_PLUGINS_OFFICIAL_DIR` and `SW_PLUGINS_LOCAL_DIR`, ADR 0027. Nothing runs a plugin yet.
- Phase 1 plugin host: an approved plugin runs in a process of its own under the Node permission model (only its own files readable, no network, no child processes, no workers, no code generation from strings, a heap limit, an empty environment, a deadline per call), reaches the network only through the core (`context.fetch`: approved `host:port` only, https, public addresses only, bounded), is verified against its approval before every start and call and stopped at once when switched off or changed, `POST /plugins/{id}/check`, `plugin.checked`, `plugin.failed` and `plugin.network.denied` records, runtime shown on the Plugins page, `definePlugin` in `@swellwright/plugin-api`, `SW_PLUGIN_MEMORY_MIB`, `SW_PLUGIN_CALL_TIMEOUT_SECONDS`, `SW_PLUGIN_IDLE_MINUTES`, ADR 0028. Not a sandbox against hostile code; sidecars, secret, panel and SSH brokers are later.
- Phase 1 plugin settings, secrets and storage: a plugin declares its settings in a closed subset of JSON Schema (`config.schema`; no patterns, `x-sw-secret` for a reference to a vault secret), the administrator fills the form in (`GET`/`PUT /plugins/{id}/config`, `plugins:manage` with a step-up, changes recorded by field name, never by value), the settings reach the plugin as `context.config` with every call, `context.secret(field)` hands over the bound vault secret only if the stored approval names its kind and the vault is unsealed (`plugin.secret.used`, never the value, once per ten minutes per secret), `context.storage` is a per-plugin key-value store with limits, one `core` request channel for network, secrets and storage, ADR 0029.
- Phase 1 declarative drivers: a plugin for a REST service as a YAML file (operations with declared parameters, up to eight `https` steps, a result shape, values only from `params`, `config`, `secret`, earlier `steps` and `each`, values in a URL encoded), interpreted by the core through the same gateway and stored approval as plugin code, checked when the plugin is found (hosts must be in `permissions.network`, settings and secrets declared), the first official plugin `notify-telegram`, `yaml` 2.9.1 in `apps/api`, ADR 0030.
- Phase 1 sidecar containers: the way plugins by others run code. The manifest names a `sidecar` (image pinned by digest, port, memory, cpus), trust `community` (`SW_PLUGINS_COMMUNITY_DIR`) may only be a sidecar or a driver, `GET /plugins/{id}/sidecar` (`plugins:manage`, step-up) returns a Docker Compose fragment (internal network with no way out, read-only, no capabilities or privileges, not root, memory/cpu/process limits, nothing published; Swellwright never starts a container), a token (HMAC over the plugin id and the digest of its files) proves each side to the other, `POST /plugins/{id}/gateway` is the only way out of the container (the approved hosts, the bound secret, its storage; 401 for anything but the token of the plugin as approved, rate-limited per address), check and call over HTTP (`/describe`, `/call`), JSON bodies up to 3 MiB, `examples/sidecar-node` as a reference run by a test, ADR 0031.
- Phase 1 API compatibility report: a pull request job (`api-compat`) compares the API description with main using the `oasdiff` release binary pinned by version and SHA-256 (no third-party action, nothing uploaded) and writes the breaking changes and the changelog to the job summary; a report, not a gate, until the first release (ADR 0012).
- Phase 1 panel parity (server): the API process opens the console at its real URLs (a GET or HEAD of a path outside `/api` without a file extension from a client that accepts HTML answers with `index.html` and the same headers as the root page; unknown `/api/...` paths and missing files stay 404), `GET /api/v1/version` also reports what the build recorded (`build.time`, `build.number`, `git.branch`, `git.commit`, `git.commitUrl`, from the optional build arguments `SW_BUILD_TIME`, `SW_BUILD_NUMBER`, `SW_GIT_BRANCH`, `SW_GIT_COMMIT`), and the new `GET /api/v1/updates` (any signed-in user, nothing written to the audit log) gives the newest GitHub release and the star count that the server fetches itself at most once a day and keeps in memory (a plain GET without identifiers, 5 s timeout, an hour before a retry after a failure, no request at start; `SW_UPDATE_CHECK=off` sends nothing, `SW_REPOSITORY`, `SW_UPDATE_API_BASE` for tests), OpenAPI 0.17.0. The console moves to real URLs.
- Phase 1 panel parity (console): the console is the panel's shell, not an imitation (ADR 0032). A fixed header of 116 px (64 px brand row, 52 px navigation row; the tabs move into the brand row from 2048 px, where pages get 10vw side padding), a hover-opening `Menubar` for the sections, 44 px header controls (Documentation, Version with the build information dialog and a glow when a release is newer, GitHub with the gold star and the count, language, account, sign out), a floating drawer with the grouped navigation below 64em, real URLs (`/dashboard/<area>/<page>`, react-router), the panel's breakpoints, `v8CssVariablesResolver`, Menu/Tooltip/Modal/Drawer/SegmentedControl/Fieldset overrides, scrollbars, toasts, the top progress bar and the Unbounded brand title. The panel's primitives are ported into `packages/ui` (page header with icon-only actions, section/settings/metric/entity cards, tables in a titled card, modal and drawer footers, overlay headers, callouts, copyable blocks, status chips, empty/loading/error states) and every page of the console (overview, roles, sessions, audit, users, tokens, vault, plugins and the sign-in screens, the step-up and password dialogs) uses them: icon-only header actions, confirmation dialogs with a red soft confirm, toasts instead of inline banners, dialogs titled with an icon and closed with a sticky footer. Behaviour is unchanged. Adds `react-router`, `react-icons`, `@mantine/notifications`, `@mantine/modals`, `@mantine/nprogress`, `@fontsource/unbounded` and `country-flag-emoji-polyfill`, pinned exactly.
- Docker build behind networks that cannot reach `binaries.prisma.sh`: the build argument `PRISMA_ENGINES_MIRROR` (default Prisma's host) is passed to the engine download in the migration stage and in `pnpm run build` (Turborepo `globalPassThroughEnv`); the pinned checksum still applies. Found by building the image on a host in Russia.
- Dependencies and security: `typescript-eslint` 8.73.0 (its estree already uses the fixed `minimatch`, so the override of ADR 0009's wait is gone), an override of `effect` (pulled in exactly by Prisma's config loader) to 3.22.4 for GHSA-7589-6fvf-x4pw, `pnpm audit` clean. GitHub: secret scanning with push protection, Dependabot security updates and CodeQL (default setup) are switched on, and a pull request job (`dependency-review`, the action pinned by commit) fails on a new dependency with a known high-severity vulnerability. Two CodeQL findings in test files are fixed.
- Phase 1 panel parity (libraries, ADR 0033): where the panel builds a component on a third-party library, the console uses the same library at the same version instead of an imitation. The lists of Users, Audit, Sessions and the vault are now `@kastov/mantine-react-table-open` tables as the panel's card tables are (filters under the head, sorting, column order, width, pinning and visibility, density, full screen, pages, a layout kept in this browser, "clear filters" and "reset table" in the card title, the library's Russian texts), the entrance of page headers, table card titles and pages is the panel's `motion` (with `MotionConfig reducedMotion="user"`), and tag colours come from `color-hash`. `ListTable` and the CSS animations that imitated these are gone. Added with them: `@mantine/dates`, `dayjs` and `clsx` as the table package's peers. `@kastov/mantine-datatable` (the panel's table for page-level lists and dialogs) waits for the first page of that kind.
- Phase 1 panel parity (Audit and Vault pages): the audit table pages, filters and counts on the server like the panel's inspector tables (`GET /audit` takes `offset` and answers `total`; the action and outcome filters are column filters under the head; the order stays the chain's, so no sorting; the list reads itself again every 25 seconds; no "load older" button, OpenAPI 0.18.0), its row action is a soft icon button in the first column and cells copy on a click, the title actions are one joined group, an event opens in a right-hand drawer of grouped cards (`DataList`, copyable values) as the panel opens a record, the date format is the panel's `HH:mm:ss, D MMMM YYYY` in every language; the vault table has the same action column (reveal, change, delete) and no custom empty state, secret types are `Badge size="lg" variant="soft"`, the key-rotation card lists its four operations as the panel lists its backend tools (a bordered card with an icon and a small soft button), the expiry of a secret is Mantine's `DatePickerInput` (a calendar icon, `D MMMM, YYYY`, Russian month names) instead of the browser's date input, the strength meter is the panel's `Progress radius="sm" size="sm"`.
- Repository hygiene checks (secrets, personal e-mail addresses, public IP addresses, forbidden patterns) and DCO check.
- Brand assets (animated banner, workflow and overview diagrams, logo, social preview), English and Russian README, support policy, release-notes categories.
